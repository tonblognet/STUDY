# Поступай

Веб-сервис для выбора московского вуза и образовательной программы. MVP объединяет официальные источники, поиск и фильтры, сравнение, избранное, freemium-доступ, личный кабинет, mock-подписку, редакторскую панель и безопасный импорт данных.

> Рабочее название. Доступность домена и товарных знаков необходимо проверить отдельно.

## Архитектура

- Next.js 16 + TypeScript, React Server Components, Tailwind CSS 4 и собственная компонентная система.
- Модульный монолит: публичные страницы, API, доступ и платежные сценарии находятся в одном приложении.
- PostgreSQL 16 + Prisma. Исторические показатели связаны с `AdmissionYear` и не перезаписываются.
- Redis предусмотрен для очереди импорта и уведомлений; в MVP импорт запускается отдельной безопасной командой.
- Платежи изолированы абстрактным сценарием; локально включен `mock`, webhook проверяет HMAC.
- Premium-редакция выполняется до сериализации API-ответа, а не средствами CSS.

Подробные продуктовые допущения, риски, 17 вариантов названия, структура страниц и roadmap находятся в [docs/PRODUCT.md](docs/PRODUCT.md).

## Быстрый запуск

Требования: Node.js 22+, pnpm 11+, Docker Desktop.

```bash
cp .env.example .env
docker compose up -d postgres redis mailpit
pnpm install
pnpm db:generate
pnpm prisma migrate dev --name init
pnpm db:seed
pnpm dev
```

Откройте `http://localhost:3000`. Mailpit доступен на `http://localhost:8025`.

## Переменные окружения

Скопируйте `.env.example` в `.env`. Для локального запуска значения PostgreSQL совпадают с `docker-compose.yml`. Замените `AUTH_SECRET` и `PAYMENT_WEBHOOK_SECRET` на длинные случайные строки. SMTP, S3 и Redis не содержат production-секретов в репозитории.

## Импорт данных

Проверить пример CSV без записи в БД:

```bash
pnpm import:sample
```

Импортер принимает локальный CSV или HTTPS URL, проверяет обязательные поля, числовые значения, год, ссылку-источник и для удаленного источника — `robots.txt`. Удаленные запросы используют идентифицируемый User-Agent и задержку. Все записи получают статус `REVIEW`; публикация без подтверждения редактора не выполняется.

## Основные маршруты

- `/` — главная и поиск;
- `/programs` — каталог, поиск, фильтры и сортировка;
- `/programs/[slug]` — баллы, места, требования, ДВИ и первоисточник;
- `/universities`, `/universities/[slug]` — каталог и страницы вузов;
- `/compare` — сравнение программ;
- `/pricing` — месячный/годовой тариф и mock trial;
- `/account` — кабинет, баллы, избранное и календарь;
- `/admin` — демонстрация редакторского контура;
- `/api/programs` — серверно редактируемая выдача premium-полей.

## Безопасность

Prisma использует параметризованные запросы; API не формирует SQL вручную. Cookies — `HttpOnly`, `SameSite=Lax`, `Secure` в production. Webhook проверяет подпись по сырому телу с constant-time сравнением. Схема содержит роли, аудит и индексы. Production-итерация должна заменить демо-auth на БД-сессии, добавить CSRF-токены для мутаций, распределенный rate limiting через Redis, одноразовые email-токены и конкретный платежный адаптер после юридической проверки.

## Известные ограничения MVP

- Каталог содержит демонстрационный набор записей; он не является полной базой московских вузов.
- Auth и избранное в UI показывают целевой поток, но полноценная запись сессий и избранного в PostgreSQL остается следующей интеграцией.
- Mock-платеж не списывает деньги. Реальный провайдер намеренно не выбран без требований юрлица и рынка.
- CSV-импорт выполняет dry-run; запись change set и планировщик BullMQ еще не включены.
- Прогноз шансов, уведомления, PDF, карта, отзывы и SEO-масштабирование отложены до проверки качества основного датасета.

## Следующая итерация

1. Подключить Prisma session adapter и полноценные email verification/password reset.
2. Реализовать редакторский change set и первые 5 адаптеров официальных источников.
3. Добавить Redis rate limiting, BullMQ и уведомления.
4. Провести контрактное тестирование платежного провайдера и webhook replay protection.
5. Добавить калькулятор шансов только после накопления проверенной истории.
