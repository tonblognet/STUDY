## Локальная подготовка

Нужны [выделенная PostgreSQL UTF8/UTC](INTEGRATION_TESTS.md) с заданным
`TEST_DATABASE_URL` и локальный Mailpit (`docker compose up -d mailpit` для
стандартной конфигурации: SMTP 1025, интерфейс 8025). Используйте вымышленные
адреса на `example.invalid` и отдельные тестовые пароли. Выполняйте по одной
ширине и одному процессу Next; две сессии откройте в двух изолированных
контекстах одного браузера. На этом компьютере не запускайте браузерную QA
одновременно с тяжёлыми gates; соблюдайте общий lock и порог 2 ГБ.

Из корня проекта, в отдельном PowerShell для QA. Повторите настройку схемы для
второй ширины, чтобы исключить влияние предыдущих аккаунтов и rate limits.
Остановите свой Next через Ctrl+C между прогонами. Mailpit можно оставить.

```powershell
$qaDb = [UriBuilder]::new($env:TEST_DATABASE_URL)
if ($qaDb.Scheme -notin @('postgres', 'postgresql') -or
    $qaDb.Host -notin @('localhost', '127.0.0.1') -or
    $qaDb.Path -cnotmatch '^/[a-z][a-z0-9_]*_test$') {
  throw 'Use a dedicated local TEST_DATABASE_URL ending in _test.'
}
$qaSchema = 'account_qa_' + [Guid]::NewGuid().ToString('N')
$qaParams = @($qaDb.Query.TrimStart('?') -split '&' | Where-Object { $_ -and $_ -notmatch '^schema=' })
$qaDb.Query = ($qaParams + "schema=$qaSchema") -join '&'
$env:DATABASE_URL = $qaDb.Uri.AbsoluteUri
$env:APP_URL = 'http://localhost:3220'
$env:CATALOG_STORAGE = 'snapshot'
$env:AUTH_SECRET = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
$env:TRUST_PROXY = 'false'
$env:SMTP_URL = 'smtp://127.0.0.1:1025'
$env:EMAIL_FROM = 'QA <qa@example.invalid>'
pnpm db:migrate
if ($LASTEXITCODE -ne 0) { throw 'QA schema migration failed.' }
pnpm start --hostname 127.0.0.1 --port 3220
```

Открывайте приложение только через `http://localhost:3220`, включая переходы
из писем. Схема `account_qa_…` используется только этим прогоном; рабочую БД
и чужие схемы не трогайте. Проверьте `/api/health` перед началом. При
повторном старте для сбоя SMTP сохраните ту же схему, `APP_URL` и `AUTH_SECRET`.

## Сценарии на 1440×1000 и 390×844

| Маршрут и действие                                                                                                                                                                                               | Что подтвердить в браузере                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/account` гостем → `/login`; открыть `/register` и зарегистрировать новый адрес                                                                                                                                 | Redirect ведёт на `/login?returnTo=/account`. Некорректные данные видны у формы, кнопка показывает ожидание, валидная отправка показывает нейтральный ответ. До подтверждения email вход запрещён.                                            |
| `/verify-email`: повторно запросить письмо, открыть новую ссылку из Mailpit, ввести пароль и подтвердить                                                                                                         | При открытии ссылки адрес остаётся неподтверждённым. Неверный пароль даёт `400`, после чего форма принимает правильный пароль с той же ссылкой. Старая и уже использованная ссылки отклоняются, после подтверждения вход доступен.            |
| `/account#security`: создать в A одну запись трекера, войти тем же аккаунтом в B, проверить список сессий в A после reload. Выйти из B, снова войти в B и открыть запись. В A нажать «Выйти на всех устройствах» | Обычный выход сохраняет доступ A; массовый завершает обе сессии. Из оставшейся открытой страницы B попробовать сохранить трекер до reload: видна ошибка истёкшей сессии, запись не меняется. После reload кабинет недоступен до нового входа. |
| `/account#tracker`, `#notifications` и `#saved`: после повторного входа создать запись с личным сроком через 1–3 дня, сохранить заметку, выбрать избранное и профиль ЕГЭ                                         | Состояние сохраняется после reload и видно во второй сессии. Напоминание появляется один раз, статус прочтения и переключатель сохраняются. Срок подписан как личный; интерфейс не обещает отправку документов или рассылку сроков.           |
| `/account#tracker`: открыть одну запись в A и B, сохранить изменение в A, затем попытаться сохранить старую версию в B                                                                                           | В B видна ошибка конфликта и доступна повторная загрузка. Ошибка не показывает успешное сохранение, версия A остаётся на сервере.                                                                                                             |
| `/forgot-password` → ссылка из Mailpit → `/reset-password`                                                                                                                                                       | Ответ на запрос нейтрален. Валидный новый пароль ведёт на `/login`; старая ссылка, старый пароль и оставшаяся сессия больше не дают доступ. Новый пароль работает.                                                                            |
| `/register`, форма повтора на `/verify-email`, `/forgot-password` при сбое SMTP                                                                                                                                  | Для валидных запросов сравнить `202` и текст формы при наличии и отсутствии подходящего адреса. Интерфейс не подтверждает доставку и не раскрывает наличие аккаунта. Ошибка доставки видна только в локальном журнале.                        |

Для последней строки остановите только свой Next, замените `SMTP_URL` на
`smtp://127.0.0.1:<свободный порт без слушателя>` и снова запустите тот же
`pnpm start`. Сохраните из предыдущих шагов подтверждённый адрес для
восстановления и заведите отдельный неподтверждённый адрес для повтора.
Сначала дождитесь серверного сообщения `Unable to process public auth request`
для запроса, который должен вызвать доставку. Для отдельной проверки отказа
на уровне SMTP используйте сценарий из
[account-db.test.ts](../tests/account-db.test.ts): там loopback SMTP отвечает
`550`. Сетевой сбой в браузерном сценарии не заменяет этот тест.

На обеих ширинах пройдите основные формы клавиатурой: видимый фокус, подписи,
порядок полей, сообщения об ошибке и занятости. Проверьте отсутствие
горизонтальной прокрутки и обрезки у длинных названий, поведение на пустом
трекере и при загрузке. Сверьте DevTools Console и Network; ожидаемые
`401`/`409` запишите отдельно от неожиданных ошибок.

В handoff запишите дату, браузер, ширину, время сборки или `.next/BUILD_ID`,
маршрут, фактический результат, ожидаемые и неожиданные ошибки. Для пропуска
укажите причину. Не прикладывайте значения cookies, URL с токенами, пароли
или содержимое тестовых писем.
