# Подбор по испытаниям — слой 02

## Результат

`matchProgram` отдельно возвращает `eligibility` (выполнены минимумы,
не выполнены, нужны сведения) и историческое сравнение. Это проверка баллов
по опубликованным требованиям, не юридическое заключение о праве поступления.
Проверка документов, льгот, действительности ЕГЭ и специальных оснований
остаётся за приёмной комиссией.

- Обязательные группы выбирают лучшую полную комбинацию без повторного
  использования предмета. Необязательные группы не повышают конкурсную сумму.
  Если введённый предмет подходит двум группам, но ещё не введена альтернатива
  для отдельного зачёта, результат требует уточнения, а не утверждает провал
  минимумов. При известных недостаточных баллах альтернативы минимум не выполнен.
- Минимумы, название/шкала ДВИ, лимит достижений должны быть `verified` и
  относиться к `trust.dataYear`. Невведённый балл отличается от нуля;
  дробные, отрицательные и выходящие за шкалу значения не оцениваются.
- Во всех формах очистка поля удаляет результат предмета. Введённые баллы
  не уменьшаются автоматически до максимума: ошибочное значение остаётся
  видимым и не участвует в расчёте. Явный ноль проверяется как результат.
  Смена выбранных предметов сохраняет пустые поля пустыми; новый предмет
  не получает автоматический балл.
- `additionalExams` содержит отдельные sourced название, минимум и максимум
  каждого испытания. При отсутствии массива используется прежняя модель ДВИ.
  Пустой массив не допускается; отсутствие ДВИ требует `not_applicable`.
- `ScoreSet.additionalExamScores` хранит результаты по ключу `slug:examId`.
  Старый `dviScore` применяется только с явным `dviProgramSlug`; интерфейс
  предлагает заново ввести общий балл для конкретной программы. Результаты
  разных программ не переносятся автоматически даже при одинаковом названии.
- Нулевые достижения не требуют лимита; ненулевые ограничиваются проверенным
  максимумом. Неизвестный предел не подменяется десятью баллами.
- Сумма сохраняется при отсутствии исторического ориентира. Разница считается
  только для проверенного предыдущего года и совпадающего
  `passingScoreExamScale`. Одна шкала ещё не подтверждает все условия конкурса:
  это справочный ориентир общего конкурса, а не прогноз для платных мест/квот.
  Непроверенная шкала у старых записей не выводится из числа предметов.
- Категории описывают разницу: от +15, от 0 до +14, ниже нуля.
  Процентов вероятности и тренда по несопоставленным годам нет.

## Фильтры и сохранение

`matchesAdmissionFilters` объединяет направление/код, вуз, уровень, форму,
бюджетные/платные места, цену, общежитие, ВУЦ, аккредитацию и статус качества.
Строгие фильтры принимают только факты кампании со статусом `verified`.
Без фильтра неизвестные значения остаются в списке. Цена требует подтверждённых
платных мест. `accreditation` — отдельное sourced поле программы; выписка
о лицензии вуза не заменяет его. В текущем каталоге оно не заполнено, поэтому
фильтр подтверждённой аккредитации честно даёт пустой результат.

Каталог открывается без ограничения исторического балла, включая программы
со шкалой выше 300. При ручном ограничении неизвестные, непроверенные и
не относящиеся к предыдущему году значения исключаются; сброс снова показывает
весь каталог. Это фильтр исторических результатов, а не оценка личных шансов.
Поля ДВИ показывают факультет, код и форму и ведут к точной программе.

Профили сохраняются в прежнем локальном/серверном хранилище. Новые поля проходят
одинаковую Zod-проверку при сохранении и чтении локальных профилей. Старые даты
формата YYYY-MM-DD нормализуются. Повреждённые профили пропускаются, не ломая
экран. База продолжает хранить JSON: новая миграция не требуется.

## Границы и проверка

Движок не создаёт новые факты приёма. Ранее подготовленные по отдельному
поручению владельца дополнения каталога, цен и сроков МГУ включены в эту же
ветку с официальными источниками; остаток описан в матрицах покрытия.
Пять творческих групп МГАХ
остаются отдельными кампаниями: перенос в Program требует сопоставления
конкурсных идентичностей, максимумов испытаний и источников, а не генерации
программ из названий. Модель нескольких испытаний проверяется синтетическими
unit-сценариями; эти данные не попадают в публичный каталог.

Проверяются альтернативы и повторный зачёт, границы минимума/максимума,
несколько ДВИ и их изоляция, статусы/годы источников, достижения, несовпадение
шкал, строгие фильтры, сохранение и PostgreSQL/HTTP round-trip.
Браузерная QA включает `/match`, `/programs`, карточку программы, `/compare`
и `/methodology` на desktop/mobile. Доказательства передачи — в HANDOFF.
