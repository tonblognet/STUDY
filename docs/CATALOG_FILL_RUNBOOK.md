## Два прохода

Работа идёт в два прохода, чтобы быстро получить базу по всем вузам, а время
агента тратить только на то, что требует чтения документов.

### Проход А — автоматическая база пакетами

20 ноября `scripts/sveden_extract.py --all` обошёл всю очередь; результаты —
в `tmp/sveden/<slug>/review.json`, итог — самый новый
`tmp/sveden/summary-*.json` (в нём больше 1 000 вузов). Если итога ещё нет,
прогон не закончен: сетевой прогон второй раз не запускать, а работать с теми
вузами, у которых `review.json` уже есть.

Перед первым пакетом один раз пересобрать отзывы по текущим правилам, без сети:
`python -X utf8 scripts/sveden_extract.py --all --offline`.

Пакет — 25 вузов: следующие строки `ждёт` из очереди, у которых в итоге прогона
статус `ok` или `partial`.

1. Выборочно сверить 3 вуза из пакета: по 2 значения с самим сайтом. Если в
   `issues` (`automatic_exclusions`) у вуза необычно много исключений —
   посмотреть причины в `tmp/sveden/<slug>/extract-report.json`.
2. `python -X utf8 scripts/sveden_extract.py <25 slug> --offline --apply` —
   пишет в `data-sources/russia/fill-<дата>.json`, пропуская программы, которые
   карточка уже показывает.
3. Новый файл дня подключить (шаг 5 ниже), проверки шага 6.
4. В `QUEUE.md` этим вузам — `частично: приём, конкурсы`; в `LOG.md` — одна
   строка на пакет (slug и итоговые числа).
5. Коммит на пакет: `data(catalog): sveden, пакет N — 25 вузов, поля N, подразделения N, перечень N`.

Вузы с другими статусами в проходе А пропускаются — они уходят в проход Б.

**Размер данных.** Файлы `fill-*.json` статически подключены в код сайта; одна
строка перечня — около 0,8 КБ, а весь проход даст десятки тысяч строк. После
каждого пакета смотреть суммарный размер `data-sources/russia/fill-*.json`,
каждые 4 пакета — полные семь проверок, включая `pnpm build`. Если файлы
перевалили за ~10 МБ или сборка заметно замедлилась либо упала по памяти —
остановить проход А и предложить владельцу способ хранения (перечни по вузу с
ленивой загрузкой или в БД). Архитектуру самостоятельно не менять.

### Проход Б — от вуза к вузу

Сверху вниз по очереди, вуз за вузом, по циклу ниже. У вузов из прохода А
шаг 2 уже сделан — начинать с шага 3. У остальных `/sveden/` читать по
статусу из итога прогона (таблица в шаге 2).

## Цикл одного вуза

### 0. Выбрать вуз

Первая строка в [QUEUE.md](catalog-fill/QUEUE.md) со статусом `в работе`,
иначе первая со статусом `ждёт`, сверху вниз. Поставить ей `в работе`.
Посмотреть, что у вуза уже есть: `pnpm data:coverage` → строка вуза в
`data-sources/russia/coverage.json`, поле `missing`.

### 1. Официальный сайт

Адрес из карточки (`website`). Проверить, что домен живой и действительно
принадлежит вузу. Если сайт переехал — новый адрес подтвердить официальной
страницей и записать в журнал.

### 2. «Сведения об образовательной организации» — `/sveden/`

Этот раздел по закону обязателен для каждого вуза России и устроен у всех
одинаково, с одинаковой микроразметкой `itemprop`. Поэтому его читает
**скрипт, а не агент**:

```
python -X utf8 scripts/sveden_extract.py --queue 20 --workers 8
python -X utf8 scripts/sveden_extract.py <slug> [<slug> …]
```

Скрипт параллельно обходит вузы и для каждого пишет
`tmp/sveden/<slug>/review.json` — готовый файл для
`scripts/fill_university.py --review`. Каждое значение — буквальный текст
своего узла разметки, проверенный разборщиком самого `fill_university.py`.
Рядом лежит `extract-report.json`: страницы, XPath строк и исключения с
причинами. Итог прогона — `tmp/sveden/summary-*.json`.

Дальше по статусу вуза в итоге прогона:

| Статус                              | Что делать агенту                                                                                                                                          |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ok`, `partial`                     | Выборочно сверить 3–5 значений с сайтом и исключения в `issues`. Затем `python -X utf8 scripts/sveden_extract.py <slug> --offline --apply`. Потом шаги 3–4 |
| `no_microdata`, `importer_rejected` | Сайт открылся, но разметки нет или она нестандартная (у `.рф`-доменов импортёр пока не принимает `officialHosts`): читать `/sveden/` вручную, как раньше   |
| `unreachable`                       | Сайт не ответил. Сначала проверить сеть (см. «Сеть» ниже), повторить прогон; если сеть в порядке — web-инструмент, хеш extract-only                        |
| `tls_untrusted`                     | Сертификат сайта не принят Windows (обычно российский удостоверяющий центр): web-инструмент, хеш extract-only. Хранилище сертификатов не менять            |
| `blocked`                           | `robots.txt` запрещает чтение, страница-заглушка или переадресация на чужой домен: web-инструмент; переезд домена подтвердить отдельно                     |
| `no_website`                        | Найти официальный сайт по реестру Рособрнадзора и записать в журнал                                                                                        |

`--apply` сливает принятые отзывы в файл дня через `fill_university.py` и
**пропускает программы, которые карточка уже показывает** (то же направление,
профиль и форма при любой записи уровня): загрузчик различает строки по
источнику и дате, поэтому без этого повторное чтение создавало бы дубли.
Не запускать `--apply`, пока другой агент пишет тот же файл дня.

`hostelInfo` скрипт не заполняет: найденные числа по общежитиям лежат в
`issues` (`hostel_microdata`), формулировку составляет агент. Контакты
приёмной комиссии, описание, конкурсы и баллы — тоже за агентом (шаги 3–4).

Проверка 20 ноября на 60 первых вузах очереди (выход через Нидерланды): 21
вуз собран, 31 не ответил, 4 с непринятым сертификатом, 2 заблокированы. Поля
совпали с ранее внесёнными вручную в 48 из 49 случаев; направления
бакалавриата и специалитета найдены повторно: Политех 165/165, Финансовый
119/119, РХТУ 63/63, РГГУ 229/229, МИСИС 82/84 (две строки исчезли с сайта).

Что скрипт читает, для справки:

| Подраздел                                                    | Что брать                                                                        | Куда в модели                                                                 |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `/sveden/common/`                                            | полное и краткое название, дата создания, адрес, телефон, email                  | `fields`: `fullName`, `shortName`, `regDate`, `address`, `telephone`, `email` |
| `/sveden/struct/`                                            | учебные подразделения: институты, факультеты, школы (без административных служб) | `faculties[]`                                                                 |
| `/sveden/education/` и его подстраницы с перечнем программ   | все реализуемые программы: код, направление, профиль, уровень, форма, срок       | `offerings[]` со статусом `pending_review`                                    |
| `/sveden/objects/`, `/sveden/grants/` или страница общежитий | есть ли общежития, сколько, условия предоставления                               | `fields.hostelInfo`                                                           |
| `/sveden/paid_edu/`                                          | документы о стоимости платного обучения                                          | пакет доказательств (стоимость по программам — в конкурсную программу, шаг 4) |

Перечень программ брать **на всех уровнях**: бакалавриат, специалитет,
магистратура, аспирантура, СПО, если вуз их публикует. Уровень записывать
буквально, как у вуза.

### 3. Раздел для поступающих

Обычно «Абитуриенту», «Приёмная комиссия», часто поддомен `priem.`, `abitur.`,
`admission.`.

- `fields.admissionsUrl`, `fields.admissionsPhone`, `fields.admissionsEmail`.
- Документы текущей кампании, каждый со ссылкой и годом: правила приёма; перечень
  вступительных испытаний и минимальных баллов; количество бюджетных мест (КЦП)
  и квоты; платные места; стоимость; сроки приёма документов и зачисления;
  индивидуальные достижения; ДВИ; особые права и БВИ; результаты прошлых лет
  (проходные баллы).
- `fields.overview` — 2–3 нейтральных предложения о вузе по его официальной
  странице «Об университете», без рекламных формулировок.

### 4. Конкурсные программы (бакалавриат и специалитет)

Если вуз опубликовал документы кампании с конкретными конкурсными группами,
добавить конкурсные программы тем же путём, что у МЭИ, МИФИ, РУДН и ВШЭ:
адаптер `data-sources/universities/<slug>/adapter.ts` с регистрацией в
`data-sources/universities/index.ts` (один адаптер на вуз) и пакет
доказательств `data-sources/release/2026-12/evidence/<дата>-<slug>-admissions.json`.

- Проходной на **бюджет** и проходной на **платное** — разные показатели,
  каждый со своим годом, этапом и источником. Бюджетное значение на платное
  не копируется. Отдельной платной истории в модели пока нет — платные
  проходные записываются в пакет доказательств и в «Нужна доработка модели».
- Минимум для подачи не равен проходному баллу.
- Общий конкурс, целевая, особая и отдельная квоты, БВИ не смешиваются.
- Если документов кампании нет или они ещё не опубликованы — конкурсные
  программы не создаются. В журнале: «конкурсы: документов <год> нет».

Если вуз очень большой (сотни конкурсных групп), в первый проход взять очную
форму головного кампуса. Остальное отметить статусом
`частично: <что осталось>` и вернуться позже, после прохода по очереди.

### 5. Записать данные

- Поля, подразделения и перечни — в **один файл на день**:
  `data-sources/russia/fill-<ГГГГ-ММ-ДД>.json`. Формат — как у
  `continuation-education-2026-11-09.json`: `checkedAt`, `sourceYear`, `scope`,
  `profiles[]` (`universitySlug`, `fields`, `faculties`, `offerings`),
  `sources[]`, `issues[]`. Все вузы этого дня — в этом же файле.
- Новый файл дня подключить одной строкой `import` и одной строкой в списке
  `mergeDirectoryEnrichment` в `lib/university-directory-details.ts`.
  Добавить короткую проверку в `lib/university-directory-details.test.ts` по
  образцу соседних.
- У каждого значения: `sourceUrl` (точная страница), `checkedAt` (UTC),
  `sourceSha256` (хеш тела ответа), `sourceYear` (год, который подтверждает
  сам источник, иначе `null`), для строк перечня — `sourceSection`.
- Инструментов два, и других на каждую партию не заводить:
  `scripts/sveden_extract.py` автоматически читает `/sveden/`,
  `scripts/fill_university.py` проверяет и сливает отзыв (автоматический или
  составленный вручную) в файл дня. Особенности конкретного сайта — правкой
  `sveden_extract.py` с тестом в `scripts/test_sveden_extract.py`.
- Сырые HTML/PDF в репозиторий не коммитить. В JSON — URL, дата и SHA-256.
- Сеть: многие региональные вузы блокируют иностранные адреса. С 20 ноября в
  Happ активен профиль «South Networks (RU) RU direct»: .ru, .su и .рф идут
  напрямую, остальное через VPN. Если вузы снова массово не отвечают — сказать
  владельцу (профиль мог смениться при обновлении Happ), VPN самому не
  настраивать. Если отдельный вуз недоступен, страницу читают через
  web-инструмент, как у ВШЭ 18 ноября, а хеш помечают как extract-only. Это не
  повод пропускать вуз.

`mergeDirectoryEnrichment` только заполняет пустые поля. Если старое значение
устарело или противоречит новому официальному источнику — не перезаписывать
молча, а записать в `issues[]` файла дня и в журнал.

### 6. Проверить и закоммитить

После каждого вуза:

```
pnpm typecheck
pnpm test lib/university-directory-details.test.ts
pnpm data:validate
pnpm data:import -- --dry-run
pnpm data:coverage
```

Открыть `/universities/<slug>` в локальном превью и убедиться, что новые данные
видны и ничего не сломалось.

Коммит на каждый вуз:
`data(catalog): <краткое имя вуза> — поля N, подразделения N, перечень N, конкурсы N`.
В тот же коммит — обновлённые `coverage.json`, строка в `QUEUE.md` (статус) и
строка в `LOG.md`.

Каждые 5 вузов и в конце сессии — все семь проверок из `AGENTS.md` по порядку,
затем push. Короткая запись в `docs/HANDOFF.md` — один абзац на партию, не на
каждый вуз.

### 7. Сразу следующий вуз

Между вузами подтверждения у владельца не спрашивать. Остановиться можно,
только если:

- кончился контекст или время сессии;
- проверки падают и не чинятся без изменения кода продукта;
- нужно решение владельца (например, изменить модель данных).

## Правила честности

Действуют полностью правила навыка `$postupai-data-integrity`. Коротко:

- Источник — только официальный: домен вуза, его поддомены и официальные
  документы, ведомственные ресурсы (Минобрнауки, Рособрнадзор). Агрегаторы
  (ucheba.ru, tabiturient, postupi.online, vuzopedia и подобные) — только чтобы
  найти ссылку на официальную страницу, никогда не как источник значения.
- Не найдено — значит `null` / `pending_review` / «не опубликовано». Не ноль,
  не прошлогоднее значение, не оценка.
- Год значения — тот, который указан в самом источнике. Значения 2025 не
  переносятся в 2026.
- Страница перечня программ не подтверждает, что в этом году по программе
  идёт приём.
- Наличие общежития не означает гарантии места.

## Особые случаи

| Ситуация                                                                    | Что делать                                                                                                        |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Сайт не открывается, ошибка, редирект на HTTP, страница-заглушка с HTTP 200 | записать попытку в журнал, статус `пропуск: сайт недоступен <дата>`, идти дальше; вернуться после прохода очереди |
| Военный, силовой или закрытый вуз, приём только через ведомство             | заполнить публичные сведения, статус `частично: закрытый приём`                                                   |
| Духовная организация, нет приёма на программы высшего образования           | заполнить публичные сведения, статус `готово`, в заметке — какой приём есть                                       |
| Лицензия прекращена или вуз ликвидирован                                    | не удалять; записать с источником в журнал, статус `пропуск: <причина>`                                           |
| Филиал                                                                      | собственный `/sveden/` филиала, если есть; иначе — данные головного вуза, относящиеся к филиалу                   |

## Отчёт владельцу в конце сессии

По-русски, коротко, без технических подробностей:

- какие вузы пройдены (имя, статус);
- сколько найдено: поля, подразделения, программы перечня, конкурсные программы;
- что не нашлось и почему;
- что записано в «Нужна доработка модели»;
- какой вуз следующий.
