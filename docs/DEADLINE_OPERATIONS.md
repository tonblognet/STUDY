# Фоновые напоминания о личных сроках

В Compose профиль `reminders` запускает worker рядом с web. Процесс читает
PostgreSQL напрямую под отдельной ролью. Первый цикл выполняется сразу, затем
цикл повторяется через минуту после завершения предыдущего. Для приёмки можно
запустить один цикл командой `node --import tsx scripts/deadline-worker.ts --once`.
Команда `--status` проверяет свежесть записи `personal_deadlines` в
`WorkerHeartbeat` и возвращает ненулевой код при возрасте больше пяти минут.

## Когда создаётся напоминание

В кабинете отображается один экземпляр напоминания на личный срок, включая
просроченный. У worker и запроса кабинета общий ключ из пользователя, записи и
точной даты UTC, совместимый со старыми уведомлениями. Оба пути проверяют
настройку и запись трекера под блокировкой пользователя. После закрытия или
отзыва заявки worker исключает её из очереди. Если опубликованный каталог
не содержит однозначной программы, текст остаётся общим.

Письма доступны отдельно. Оператор включает `DEADLINE_EMAIL_ENABLED=true` в
web и worker после приёмки SMTP. Пользователь с подтверждённым адресом
включает письма в разделе «Уведомления». У новых и существующих аккаунтов
настройка выключена по умолчанию. Каждое письмо содержит дату предстоящего
личного срока и ссылку на кабинет. В очередь попадают будущие сроки в пределах
семи дней. Перед выдачей задания worker повторно проверяет согласие,
подтверждение email, владельца, дату и статус трекера. Отправка, начатая до
изменения настройки, может завершиться после него.

## Повтор и сверка

Задание хранит идентификаторы и сроки, а адрес и текст собираются в памяти
перед отправкой. Один ключ соответствует одной записи и дате. Claim
сохраняется до обращения к SMTP. Следующая транзакция проверяет согласие,
трекер и актуальную аренду под блокировкой владельца, затем запускает запрос.
Worker ожидает ответ SMTP после освобождения блокировок.

| Состояние   | Значение и действие                                                                                                                                  |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PENDING`   | Ожидает отправки. После явного ответа SMTP 4xx задержка растёт, максимум четыре попытки с одним Message-ID.                                          |
| `SENDING`   | Worker взял задание. Если lease истёк, следующий цикл отмечает `UNKNOWN`.                                                                            |
| `SENT`      | SMTP принял письмо. Проверка доставки в почтовый ящик выполняется отдельно.                                                                          |
| `FAILED`    | SMTP отклонил письмо окончательно либо исчерпаны временные повторы. Проверить сервис и его журнал недоставки.                                        |
| `UNKNOWN`   | Разрыв связи или прерывание могло произойти после приёма письма. Сверить журнал провайдера по Message-ID. Повтор автоматически не запускается.       |
| `CANCELLED` | Согласие, дата, статус или подтверждение email изменились до отправки. Если условия снова выполняются, worker возобновит задание под прежним ключом. |

Цикл выбирает до 20 владельцев и 200 записей на владельца для кабинета, до 100
новых заданий и до 20 отправок за один проход. Уже созданные записи исключаются
до ограничения выборки. После сбоя проверьте возраст heartbeat и количество
`FAILED`/`UNKNOWN` перед возобновлением. Журналы worker содержат только время,
тип события и агрегаты. Не пересылайте содержимое почты или строки подключения
в отчёт.

Для паузы рассылки выключите флаг в обоих сервисах. Для обслуживания схемы или
восстановления остановите worker. Перед повторным стартом подтвердите состояние
очереди и настроек, запустите одну итерацию на закрытом staging и проверьте
heartbeat, дедупликацию и почтовый ящик. SMTP, провайдерский журнал и внешняя
доставка входят в приёмку окружения. [Развёртывание](SELF_HOSTING.md).
