## Первый доступный пакет

Проверки живого процесса и готовности к трафику должны различаться. Готовность
требует корректной конфигурации, миграций и опубликованного каталога в БД;
snapshot-preview не выдаётся за готовый production. Серверная диагностика
использует ограниченные структурированные события без тела запроса, cookies,
query strings, сообщения исключения и полных стеков.

Docker build должен генерировать Prisma для целевой ОС, исключать локальные
состояния/секреты/временные файлы и выпускать отдельные web/migration targets.
Production-образ запускается непривилегированным пользователем. Контейнерная
проверка выполняется на Linux CI: локальный Docker на хосте отсутствует.
Проверяется и origin за reverse proxy: разрешённый origin берётся из APP_URL,
а не из клиентского Host/forwarded заголовка.

До изменений прочитаны установленные Next self-hosting/route-handler/
instrumentation guides, Dockerfile, dockerignore, health, origin validation,
Prisma/schema, DB/HTTP suites и инструкции DEPLOYMENT/SECURITY. Выявлены
отсутствие генерации Prisma в Docker build и неполное исключение локальных
каталогов из build context.

Реализация включает закрытый HTTPS-профиль [Docker Compose и Caddy](SELF_HOSTING.md),
отдельные идентичности web, миграций, worker и оператора. Добавлены команда
первоначального назначения SUPERADMIN с аудитом и отзывом старых сеансов,
фоновая очередь личных напоминаний с явным согласием на письма и heartbeat,
изолированная репетиция резервного восстановления. [Напоминания](DEADLINE_OPERATIONS.md).
[Восстановление](BACKUP_RESTORE.md).

В CI проверяются сборка трёх Linux-артефактов, миграция тестовой PostgreSQL,
старт отдельного worker, HTTP и статика standalone. Проверка CI подтверждает
контейнеры с синтетической БД. На staging дополнительно проверяются внешние
доставки, роли реального облака, сертификат, rollback, RPO/RTO и отзыв доступа.

## Полная приёмка слоя

- [ ] Воспроизводимые web/migration artifacts, staging/production-конфигурация,
      reverse proxy и HTTPS; домен и регион определены владельцем.
- [ ] Liveness/readiness, безопасные события, рабочие метрики/алерты и
      подтверждённая доставка ответственному.
- [ ] Фоновые напоминания при закрытом кабинете, доставка, повторы,
      дедупликация, часовой пояс и heartbeat; фактическая внешняя почта.
- [ ] Release/migrate/rollback и безопасное начальное назначение staff-роли.
- [ ] Backup/restore воспроизведены; фактические RPO/RTO и rollback записаны.
- [ ] Performance/accessibility и внешний security/legal контроль; блокирующие
      замечания закрыты, ограничения и ответственные определены.
- [ ] Семь локальных gates, нужная browser QA, самопроверка, CI текущего head,
      handoff и merge.

## Зависимости и границы

Домен, сервер/облако, production БД, backup, SMTP и получатель алертов пока
отсутствуют. Требуемые действия: [OWNER_SETUP_CHECKLIST.md](OWNER_SETUP_CHECKLIST.md).
Артефакт и локальная проверка не доказывают production deployment, внешнюю
доставку или выполнение RPO/RTO. Техническая подготовка продолжается без них;
слой 07 не объявляется завершённым по первому пакету.

Реальная банковская приёмка обязательна перед публичным запуском,
[issue #10](https://github.com/tonblognet/STUDY/issues/10); оплаты выключены.
Полноценный AI остаётся после Stage 1. Операционная проверка каталога идёт
отдельно и не меняет trust-статусы автоматически.
