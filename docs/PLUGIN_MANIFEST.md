# Codex plugin manifest

Плагины устанавливаются каждым разработчиком из Plugins в Codex под своим аккаунтом. Версии намеренно не закреплены: доступность и обновления управляются Codex, а воспроизводимый проектный процесс хранится в репозитории.

## Основной набор для «Поступай»

| Плагин/возможность | Для чего                                                     |
| ------------------ | ------------------------------------------------------------ |
| Build Web Apps     | Реализация и проверка React/Next.js интерфейса               |
| Product Design     | UX-аудит, пользовательские сценарии и визуальная целостность |
| Vercel             | Next.js, production checks и будущий deployment workflow     |
| Browser            | Проверка локального приложения в реальном браузере           |
| OpenAI Docs        | Актуальные правила Codex, skills, plugins и OpenAI API       |

## Локальные навыки владельца, полезные обоим

- `playwright` — браузерные E2E-проверки;
- `ui-ux-pro-max` — дополнительный UI/UX-анализ;
- `imagegen` — создание оригинальных визуальных материалов при необходимости.

Если этих локальных навыков нет у второго разработчика, это не блокирует работу: обязательная командная логика находится в `.agents/skills`, а UI-проверки описаны в `$postupai-ui-verification`.

## Проектные навыки, устанавливать не нужно

- `$postupai-layer-delivery`;
- `$postupai-data-integrity`;
- `$postupai-ui-verification`.

Они автоматически доступны после клонирования репозитория и перезапуска Codex.

## Проверка паритета

На обоих компьютерах Codex должен одинаково ответить на вопросы:

1. Какой слой активен?
2. Можно ли начинать следующий слой до merge текущего?
3. Какие семь команд обязательны перед передачей?
4. Что делать с непроверенным проходным баллом?
5. Какие маршруты проверить после UI-изменений?

Совпадение ответов, зелёный CI и один Git commit важнее, чем полное совпадение локальных caches или истории чатов.
