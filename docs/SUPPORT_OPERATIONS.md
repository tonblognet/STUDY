# Работа с обращениями поддержки

Слой 06, 10 ноября 2026. Это инструкция для подготовленного интерфейса;
ответственный оператор, часы работы и фактические контакты перед запуском
ещё должны быть определены владельцем. `SUPPORT_RESPONSE_HOURS=48` задаёт
целевой следующий ответ в календарных часах, без учёта выходных. Это не
договорное обещание SLA и не автоматически отправляемое уведомление.

## Начало смены и первичный разбор

1. Войти отдельным аккаунтом сотрудника SUPPORT, ADMIN или SUPERADMIN;
   проверить актуальность доступа. Паролями и сессиями не делиться.
2. Открыть `/admin/support`, обновить список и проверить открытые/находящиеся
   в работе обращения. Фильтр «Только назначенные мне» ограничивает очередь;
   перед завершением смены проверить и неназначенные обращения.
3. Открыть диалог, прочитать предыдущую переписку и целевой срок. Назначить
   обращение себе, установить приоритет и статус «В работе». Старое обращение
   без срока остаётся «Срок не задан»; это не означает отсутствия проблемы.
4. Ответить через диалог. Ответ сотрудника переводит обращение в ожидание
   пользователя и записывает первое время ответа, если его ещё не было.
   Повторные ответы не переписывают эту первоначальную дату.

Приоритет HIGH используется для недоступности аккаунта, подозрения на чужой
доступ, несоответствия оплаченного доступа или сбоев, затрагивающих нескольких
пользователей. Это операционное правило разбора, не автоматическое определение
серьёзности. Фактического ответственного за эскалации нужно назначить до запуска.

## Проверка проблемы и эскалация

| Категория                                    | Действие сотрудника                                                                                                                                                                                                                     |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Данные каталога                              | Запросить ссылку на страницу и официальный источник. Передать редактору; не обещать изменение баллов, мест или стоимости до проверки происхождения.                                                                                     |
| Вход и аккаунт                               | Уточнить наблюдаемый шаг и время ошибки. Использовать штатное восстановление. Не просить пароль, одноразовый код, секрет 2FA, cookie или токен восстановления.                                                                          |
| Оплата                                       | Уточнить внутренний номер платежа из `/account/billing`, время и показанный статус. Передать ADMIN/SUPERADMIN; сотрудник SUPPORT не выполняет финансовые команды. Сверка и возврат — по [BILLING_OPERATIONS.md](BILLING_OPERATIONS.md). |
| Подозрение на чужой доступ или массовый сбой | Прекратить обычные рекомендации, сохранить безопасные ID/время/шаги воспроизведения и передать назначенному владельцем ответственному. Не обещать разрешение без технической проверки.                                                  |

Не просить PAN/CVV, фотографии карты, банковский пароль или доступ к Госуслугам.
Не копировать полную переписку и персональные данные в публичный GitHub issue
или логи. Для технического дефекта использовать обезличенные шаги, маршрут,
время и разрешённые идентификаторы. Отправка сообщений во внешнюю почту не
происходит автоматически при ответе в интерфейсе; пользователь читает историю
на `/support`.

## Статусы, конфликты и окончание смены

- «Открыто» и «В работе» требуют внимания сотрудника. После нового сообщения
  пользователя из ожидания/закрытого состояния появляется новый целевой срок;
  повтор сообщения в уже открытом обращении не обнуляет прежнее ожидание.
- «Ждём вашего ответа» устанавливается отправленным ответом сотрудника;
  переход в него без сообщения отклоняется. Срок ответа сотрудника в этом
  состоянии не показывается как просроченный.
- После подтверждённого решения установить «Решено» или «Закрыто». Пользователь
  может закрыть или повторно открыть обращение; новое сообщение также его
  открывает. История и первоначальный ответ сохраняются.
- При сообщении о конфликте версии обновить переписку, прочитать новые данные
  и только затем повторить действие. Несохранённый пользовательский черновик
  остаётся в текущей вкладке; не обещать его сохранение после закрытия браузера.
- Перед завершением смены проверить незавершённые и просроченные обращения,
  передать безопасный контекст ответственному по утверждённому процессу.
  Можно снять назначение; назначить другого сотрудника через этот UI нельзя.

Список и страницы сообщений ограничены 20 записями; старые сообщения
подгружаются с проверкой версии диалога. Максимум 20 незакрытых обращений на
пользователя и 1 000 сообщений в диалоге. При достижении лимита сообщений
создать новое обращение и указать номер предыдущего без копирования секретов.

ADMIN/SUPERADMIN управляют staff-ролями на `/admin/users`: смена роли отзывает
сессии и незавершённые подтверждения target. Своя роль и SUPERADMIN для
обычного ADMIN защищены. Начальное назначение первого привилегированного
аккаунта и доступ к окружению относятся к подготовке эксплуатации слоя 07;
публичного обхода авторизации здесь нет.
