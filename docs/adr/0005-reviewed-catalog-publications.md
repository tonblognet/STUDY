# ADR 0005: атомарная редакционная публикация каталога

Дата: 22 сентября 2026. Слой 01.

## Проблема

Публичные страницы читали TypeScript/JSON, а административный PATCH изменял
EducationProgram в PostgreSQL. Эти пути не были связаны: правка в базе не
обновляла карточку. Импорт делал последовательные записи без общей транзакции.

## Решение

В режиме `CATALOG_STORAGE=database` все публичные программы, организации,
профили происхождения, образовательные перечни и дополнительные кампании
читаются из одной опубликованной CatalogRevision. CatalogHead указывает на
действующую версию. Payload и diff версионируются целиком; SHA-256 проверяет
целостность, но не доказывает истинность сведений.

Импорт и редакторская форма создают REVIEW, не меняя сайт. Редактор видит
старые и новые значения вместе с источниками и отдельно подтверждает публикацию
или отклоняет изменение с обоснованием. Каждый импорт указывает базовую версию.
Старый черновик нельзя опубликовать поверх более свежего. Повтор одинакового
payload относительно той же базы возвращает существующую запись. Отклонённый
payload требует исправления или изменения provenance перед повторной подачей.

Транзакция блокирует единственную строку CatalogHead через PostgreSQL FOR UPDATE.
При публикации связанные University/EducationProgram обновляются, решение и
audit записываются, указатель переключается. Любая ошибка откатывает всё.
История хранит полное состояние, включая неизвестные и конфликтующие факты.
Ранее записанные MetricValue/UniversityFactValue сохраняются как архив прежнего
импортера; новые публикации версионируются в CatalogRevision.

Публичное чтение выполняется на запрос; React cache объединяет повторные чтения
внутри одного серверного рендера. Между запросами снимок не кэшируется. Следующий
запрос видит опубликованную версию без перезапуска приложения. Открытую ранее
страницу пользователь обновляет обычным способом.

## Границы

- `CATALOG_STORAGE=snapshot` — явный режим демонстрации/офлайн-разработки.
  Редакторские HTTP-команды в нём запрещены. Он не является fallback при сбое БД.
- Файлы репозитория остаются входом для первоначального импорта, специализированных
  извлечений и fixture-тестов. Их изменение само по себе не публикуется в режиме БД.
- Полный архив МГУ 2011–2025 остаётся статическим приложением источников. Условия
  текущих конкурсных групп и связанная история в карточках читаются из публикации.
- Обнаружение маркеров адаптером не извлекает факты и всегда требует review.
  Извлечение из произвольного HTML/PDF не объявляется реализованным.
- Интерфейс редактирует стоимость и бюджетные/платные места. Другие поля проходят
  через экспорт, подготовку структурированного снимка и ту же очередь проверки.
- Проверенные ранее точные URL справочника сохраняются, в том числе ссылки на
  государственные реестры; новые программные источники проверяются по доменам вуза.
- Запись всех данных одним снимком подходит текущим 162 организациям/185 программам.
  При значительном росте нужны измерения, серверная пагинация и проекции чтения;
  это не заявление о готовности к каталогу всей России.

## Проверка

Тесты на настоящей PostgreSQL используют отдельную автоматически созданную схему
в БД с суффиксом `_test`. Проверяются миграции, параллельные импорты, повторные
решения, устаревшие формы, откат при ошибке аудита, неизменяемость опубликованных
снимков и HTTP-доступ. Тестовый сервер запускает production build.
